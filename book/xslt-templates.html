The sxml Book

Templates and Modes

Template rules

A template rule has a match pattern and a body. The body is a sequence constructor: literal result elements (any element that is not in the XSLT namespace, such as <p>), text, and instructions. This stylesheet makes an HTML page of the draft, with one rule for each kind of element:

draft.xsl:

<xsl:stylesheet version="4.0" expand-text="yes"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    exclude-result-prefixes="xs">
  <xsl:output method="html" indent="yes"/>

  <!-- "show" writes the editorial notes into the page. -->
  <xsl:param name="notes" select="'hide'"/>

  <xsl:template match="/">
    <html>
      <head>
        <title>{rfc/front/title}</title>
      </head>
      <body>
        <h1>{rfc/front/title}</h1>
        <!-- The same sections, processed twice in two modes. -->
        <xsl:apply-templates select="." mode="toc"/>
        <xsl:apply-templates select="rfc/middle/section"/>
      </body>
    </html>
  </xsl:template>

  <!-- The page: one rule for each kind of element. -->
  <xsl:template match="section">
    <section id="{@anchor}">
      <h2>{name}</h2>
      <xsl:apply-templates select="* except name"/>
    </section>
  </xsl:template>

  <xsl:template match="t">
    <p><xsl:apply-templates/></p>
  </xsl:template>

  <xsl:template match="t[@anchor]" priority="1">
    <p id="{@anchor}" class="requirement"><xsl:apply-templates/></p>
  </xsl:template>

  <xsl:template match="xref">
    <a href="#{@target}">{if (node()) then . else @target}</a>
  </xsl:template>

  <xsl:template match="bcp14">
    <span>
      <xsl:attribute name="class">
        <xsl:call-template name="strength">
          <xsl:with-param name="keyword" select="normalize-space()"/>
        </xsl:call-template>
      </xsl:attribute>
      <xsl:value-of select="."/>
    </span>
  </xsl:template>

  <xsl:template match="cref">
    <xsl:if test="$notes = 'show'">
      <span class="note">[{@source}: {normalize-space()}]</span>
    </xsl:if>
  </xsl:template>

  <xsl:template match="dl | dd">
    <xsl:copy><xsl:apply-templates/></xsl:copy>
  </xsl:template>

  <xsl:template match="dt">
    <dt id="{@anchor}"><xsl:apply-templates/></dt>
  </xsl:template>

  <xsl:template match="sourcecode">
    <pre>{.}</pre>
  </xsl:template>

  <!-- A named template, called with a typed parameter. -->
  <xsl:template name="strength">
    <xsl:param name="keyword" as="xs:string"/>
    <xsl:choose>
      <xsl:when test="$keyword = ('MUST', 'MUST NOT', 'REQUIRED', 'SHALL', 'SHALL NOT')">bcp14 absolute</xsl:when>
      <xsl:when test="starts-with($keyword, 'SHOULD') or contains($keyword, 'RECOMMENDED')">bcp14 recommended</xsl:when>
      <xsl:otherwise>bcp14 optional</xsl:otherwise>
    </xsl:choose>
  </xsl:template>

  <!-- The table of contents: the mode "toc". -->
  <xsl:template match="/" mode="toc">
    <ol class="toc">
      <xsl:apply-templates select="rfc/middle/section" mode="toc"/>
    </ol>
  </xsl:template>

  <xsl:template match="section" mode="toc">
    <li>
      <a href="#{@anchor}">{name}</a>
      <xsl:if test="section">
        <ol>
          <xsl:apply-templates select="section" mode="toc"/>
        </ol>
      </xsl:if>
    </li>
  </xsl:template>

Let's read it rule by rule:

  • match="/" matches the document node, where every transformation starts. It writes the page, and xsl:apply-templates processes the draft's sections where the page's body goes.
  • match="section" writes a section with a heading, and processes the section's children except its name. A nested section matches the same rule, so sections nest in the page as deep as in the draft.
  • match="t" writes a paragraph, and match="xref" a link. An xref with no content shows its target's anchor for now; Keys, Numbers and Grouping makes "Section 4" of it.
  • match="dl | dd" uses xsl:copy, which copies the element without its attributes or children: the content comes from the rules again. A pattern with | matches either kind of node.
  • The text in between is copied by the built-in rule, so the words of a paragraph pass through with the elements inside them turned into HTML.

xsl:apply-templates is the engine of XSLT. It selects nodes (with select, or the children by default), and for each one it finds the best matching rule. The xsl:output element says how to write the result: here as HTML, indented. The html method writes the <!DOCTYPE html> and the meta element for the encoding itself.

Text value templates

With expand-text="yes" on the stylesheet, curly braces in text work as they do in XQuery: {name} is replaced by the value of the expression name, the section's title. In attributes of literal result elements, curly braces always work; they are attribute value templates: id="{@anchor}" gives the HTML element the draft's anchor, so the links work. Without expand-text, you write <xsl:value-of select="name"/> instead, as older stylesheets do and as the bcp14 rule does once.

Priorities

Two rules match a requirement: t and t[@anchor]. When several rules match, the one with the highest priority wins. A rule can state its priority, as the second one does. Otherwise, the priority comes from the pattern: a pattern with a predicate or several steps is more specific than a plain name, and gets a higher default priority (0.5 against 0). So the priority="1" above isn't even needed; it just makes the intent clear. The requirements get an id and a class:

$ sxml transform draft.xsl vane.xml | grep -A2 'id="req-1"'
      <p id="req-1" class="requirement">A <a href="#term-flag">flag</a>
      <span class="bcp14 absolute">MUST</span> be in exactly one of the states "stable",
      "rolling-out" and "paused".</p>

Patterns are not expressions that are evaluated from the top: a pattern tests a node. t matches any t element anywhere, section/t a paragraph whose parent is a section (not one in the abstract), and section[1] a section that is the first section child of its parent.

Named templates and parameters

The bcp14 rule shows several more things:

  • A template with a name instead of a match is a named template. xsl:call-template calls it, and xsl:with-param passes its parameters, which can have types: strength takes an xs:string.
  • xsl:attribute makes an attribute from a sequence constructor, here the text the named template writes.
  • xsl:choose picks the first xsl:when whose test is true, or xsl:otherwise. There is also xsl:if for a single test, as in the cref rule.
  • A stylesheet declares every prefix it uses, xs too: here xmlns:xs="http://www.w3.org/2001/XMLSchema" on xsl:stylesheet makes xs:string a type, and exclude-result-prefixes="xs" keeps the declaration out of the result. Unlike XPath and XQuery, XSLT predeclares no prefix but xml; an undeclared one is an error (XPST0081 in an expression or a type such as as, XTSE0280 in a name such as mode).

xsl:param at the top level declares a stylesheet parameter, with a default. notes decides whether the editorial notes show, and --param sets it from the command line:

$ sxml transform --param=notes=show draft.xsl vane.xml | grep 'class="note"'
      <span class="note">[AM: Should an owner be able to change the duration?]</span></p>
      <span class="note">[AB: This needs a requirement anchor of its own.]</span></p>

Modes

The page processes the same sections twice: once for the table of contents and once for the content. A mode is a named set of rules. xsl:apply-templates mode="toc" uses only the rules of the toc mode, so a section there makes a list item with a link, not a section element. Each mode has its own built-in rules, too, which is why the toc mode has a rule for the document node: without it, the built-in rule would copy all the text of the draft into the table of contents.

A mode can do more than a part of the page. The rest of draft.xsl is a second rendering of the whole draft, as plain text in the style of an RFC: section numbers, paragraphs indented by three spaces and wrapped at 72 columns, and a reference written as [RFC2119]:

  <!-- Plain text in the style of an RFC: the mode "text". -->
  <xsl:template match="/" mode="text">
    <xsl:apply-templates select="rfc/front/title, rfc/middle/section" mode="text"/>
  </xsl:template>

  <xsl:template match="title" mode="text">
    <xsl:text>{.}&#10;&#10;</xsl:text>
  </xsl:template>

  <xsl:template match="section" mode="text">
    <xsl:variable name="number" select="
        string-join(ancestor-or-self::section ! (count(preceding-sibling::section) + 1), '.')"/>
    <xsl:text>{$number}.  {name}&#10;&#10;</xsl:text>
    <xsl:apply-templates select="* except name" mode="text"/>
  </xsl:template>

  <xsl:template match="t | dd" mode="text">
    <xsl:variable name="text">
      <xsl:apply-templates mode="text"/>
    </xsl:variable>
    <xsl:variable name="indent" select="if (self::dd) then '      ' else '   '"/>
    <!-- Lines of at most 72 characters, indented. -->
    <xsl:value-of select="replace(normalize-space($text),
                                  '(.{1,' || 72 - string-length($indent) || '})( |$)',
                                  $indent || '$1&#10;')"/>
    <xsl:text>&#10;</xsl:text>
  </xsl:template>

  <xsl:template match="dl" mode="text">
    <xsl:apply-templates select="*" mode="text"/>
  </xsl:template>

  <xsl:template match="dt" mode="text">
    <xsl:text>   {.}&#10;</xsl:text>
  </xsl:template>

  <xsl:template match="sourcecode" mode="text">
    <xsl:value-of select="tokenize(., '&#10;')[normalize-space()] ! ('     ' || . || '&#10;')"
                  separator=""/>
    <xsl:text>&#10;</xsl:text>
  </xsl:template>

  <xsl:template match="xref[empty(node())]" mode="text">[{@target}]</xsl:template>

  <xsl:template match="cref" mode="text"/>

The t rule applies the rules of the mode to the paragraph's children inside an xsl:variable, so the variable holds the paragraph's text with every xref and bcp14 already turned into text. normalize-space joins its lines, and one replace breaks it again into lines of at most 69 characters plus the indent: (.{1,69})( |$) takes as many characters as fit before a space or the end. The section number is the position of each enclosing section among its siblings, joined with dots.

xsl:value-of with separator="" joins the lines of the ABNF without a space between them, and xsl:text writes text exactly, which keeps the whitespace of the stylesheet out of the result: &#10; is a line feed.

Starting somewhere else

A transformation normally starts by applying templates to the document node in the default mode. --initial-mode starts in another mode. The toc mode alone is a table of contents:

$ sxml transform --initial-mode=toc draft.xsl vane.xml
<ol class="toc">
  <li><a href="#intro">Introduction</a><ol><li><a href="#terminology">Terminology</a></li></ol></li>
  <li><a href="#states">Flag States</a></li>
  <li><a href="#messages">Messages</a><ol><li><a href="#rollout">Rollout</a></li><li><a href="#status">Status</a></li></ol></li>
  <li><a href="#pause">Pause</a></li>
  <li><a href="#security">Security Considerations</a></li>
  <li><a href="#iana">IANA Considerations</a></li>

--initial-template calls a named template instead of applying templates. A stylesheet that needs no input names its starting template xsl:initial-template, and runs without a document:

bcp14.xsl:

<xsl:stylesheet version="4.0" expand-text="yes"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
  <xsl:output method="text"/>

  <!-- The key words of BCP 14, from strongest to weakest. -->
  <xsl:variable name="keywords" select="'MUST', 'MUST NOT', 'REQUIRED', 'SHALL',
      'SHALL NOT', 'SHOULD', 'SHOULD NOT', 'RECOMMENDED', 'NOT RECOMMENDED',
      'MAY', 'OPTIONAL'"/>

  <xsl:template name="xsl:initial-template">
    <xsl:text>BCP 14 has {count($keywords)} key words: {string-join($keywords, ', ')}.&#10;</xsl:text>
  </xsl:template>
</xsl:stylesheet>

$ sxml transform bcp14.xsl
BCP 14 has 11 key words: MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, NOT RECOMMENDED, MAY, OPTIONAL.
