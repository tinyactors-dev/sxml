The sxml Book

Drawing the Machine

A state machine is easiest to read as a picture: boxes for the states, arrows for the transitions. Project: Drawing Diagrams with SVG built a module that draws any diagram description, draw.xqm, with a computed layout. This section turns the machine into such a description and draws it, and then draws what the fix of Checking What the Schema Cannot changed.

draw.xqm here is a link to the module in the svg directory, so the machine is drawn by the same code as every other diagram of the book.

The machine as a diagram

A diagram description is a diagram element with node and edge elements, in no namespace. For the machine, each state is a node, and each pair of states that transitions connect is an edge, labelled with the events that lead from one to the other:

machine-diagram.xq:

(: A Vane machine (the context item) as a diagram description for
   draw.xqm: a node for each state, the initial state first, and an edge
   for each pair of states that transitions connect, labelled with their
   events. A transition without a target is an edge from its state to
   itself. With before=FILE, the parts that FILE's machine does not have
   get the class "added", and the parts only FILE has the class
   "removed". :)
declare default element namespace "http://www.w3.org/2005/07/scxml";
declare namespace vane = "urn:example:vane";
declare option output:indent "yes";

declare variable $before as xs:string external := "";

(: The states of a machine, initial first, and its edges as records. :)
declare function local:states($machine as element(scxml)) as xs:string* {
  let $initial := string($machine/@initial)
  return ($initial, $machine//state/@id[. ne $initial] ! string())
};

declare function local:edges($machine as element(scxml)) as record(from, to, label)* {
  for $transition in $machine//transition
  let $from := string($transition/../@id)
  group by $from, $to := string(($transition/@target, $from)[1])
  return { "from": $from, "to": $to,
           "label": string-join(distinct-values($transition/@event ! tokenize(.)), ", ") }
};

declare function local:class($present as xs:boolean, $added as xs:boolean) as attribute()? {
  if ($added and $present) then attribute class { "added" }
  else if (not($present)) then attribute class { "removed" }
  else ()
};

let $machine := /scxml
let $old := if ($before) then doc($before)/scxml else $machine
let $states := local:states($machine)
let $old-states := local:states($old)
let $edges := local:edges($machine)
let $old-edges := local:edges($old)
let $key := fn($edge) { $edge?from || " " || $edge?to }
return <diagram xmlns="" title="{ $machine/@name }">{
  for $state in distinct-values(($states, $old-states))
  return <node id="{ $state }" label="{ $state }">{
    local:class($state = $states, not($state = $old-states))
  }</node>,
  for $edge in ($edges, $old-edges[not($key(.) = $edges ! $key(.))])
  return <edge from="{ $edge?from }" to="{ $edge?to }" label="{ $edge?label }">{
    local:class($key($edge) = $edges ! $key(.), not($key($edge) = $old-edges ! $key(.)))
  }</edge>
}</diagram>
  • The initial state comes first, because the layout starts from the first node, and so draws it near the top.
  • The transitions are grouped by their source and target, so that two transitions between the same states make one arrow with both events on it; there is one arrow per pair, and draw.xqm gives each the id edge-FROM-TO.
  • A transition without a target stays in its state, so it is an edge from the state to itself, which draw.xqm draws as a small loop on the right of its box.
  • The edges are records, record(from, to, label), so that the edges of two machines can be compared by their source and target, below.

Cycles

A machine is full of cycles: stable to checking and back. The layered layout of draw.xqm puts every node in a layer so that every edge points down, so first it turns round the edges that close a circle, found by a depth-first search that starts at the first node, the initial state:

$ sxml xquery --context-item=flag.scxml machine-diagram.xq \
  | sxml xquery --method=adaptive --context-item=- \
      --expression='import module namespace draw = "urn:example:draw" at "draw.xqm"; for $position in draw:reversed(/diagram) return /diagram/edge[$position] ! `{@from} -> {@to}`'
"checking -> stable"
"rolling-out -> stable"
"paused -> stable"

--context-item=- reads the diagram from the pipe. The three edges from below back to stable are the ones turned round: drawn, they run up into stable. The edge from archived to stable closes no circle, and stays as it is. No transition leads to archived, so nothing pulls it down, and the layout puts it in the layer above stable, the one state it leads to. The flaw that check.xq reported as "unreachable state: archived" is visible in the drawing: the state sits on top, above the initial state, with an arrow that leaves it and none that arrive.

Drawing it

draw:svg makes the SVG element; an output declaration indents it:

$ sxml xquery --context-item=flag.scxml machine-diagram.xq > flag-diagram.xml
$ sxml xquery --context-item=flag-diagram.xml --output=flag.svg --expression='
    import module namespace draw = "urn:example:draw" at "draw.xqm";
    declare option output:indent "yes";
    draw:svg(/diagram)'

  </g>

Drawing a change

machine-diagram.xq takes an optional parameter, before: the file of an earlier version of the machine. States and edges that the earlier version doesn't have get the class added, and the ones only the earlier version has get removed. draw.xqm copies the classes to the SVG groups, and its style draws added parts in green and removed parts dashed in red. The fixed machine against the seed:

$ sxml xquery --context-item=flag-fixed.scxml --param=before=flag.scxml machine-diagram.xq \
  | sxml xquery --context-item=- --output=changes.svg --expression='
      import module namespace draw = "urn:example:draw" at "draw.xqm";
      declare option output:indent "yes";
      draw:svg(/diagram)'
$ sxml xpath --context-item=changes.svg '//*:g[contains-token(@class, "added")] ! `{@id}: {*:text}`'
"edge-stable-archived: flag.archived"
"edge-paused-archived: flag.archived"

The two new transitions on flag.archived are the change, and they move archived to the bottom: something now leads to it, from stable and from paused, so it goes in the layer below them, and its own transition to stable runs up. The new declaration of flag.evaluated and the new vane:implements change no state or transition, so the drawing doesn't show them; the page of Documenting the Machine in XHTML does.

The same mechanism, a diagram description with classes drawn by one module, draws the diff of call chains in Comparing Two Versions and the diff of traces in Rendering the Diff.
