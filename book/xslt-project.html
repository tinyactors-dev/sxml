The sxml Book

Project: Publishing the Specification

An Internet-Draft is written once and read in several forms: as a web page with a table of contents, as plain text in the style of an RFC, and by tools that want the requirements as data. Each new version also needs a page that says what changed since the last one. This project makes all of them from vane.xml with one script, and stops before it writes anything when the draft has a mistake that would make the published text wrong.

The pieces come from the earlier sections of this chapter. The HTML page is html.xsl and the plain text is text.xsl, both with the package spec.xsl and the module common.xsl from Many Outputs, Functions and Packages. New are a check, a JSON output and the page of changes.

The script

publish.sh:

#!/bin/sh
# Publishes a draft into the directory site/: checks it, then writes the
# HTML page, the plain text, the requirements as JSON and a page of the
# changes since the earlier draft. Stops at the first step that fails.
#
# Usage: sh publish.sh [DRAFT [EARLIER-DRAFT]]
set -e
draft=${1:-vane.xml}
earlier=${2:-vane-00.xml}

sxml validate --schema=vane.xsd "$draft"
sxml xquery --param=draft="$draft" publish-check.xq

mkdir -p site
sxml transform --force --output=site/vane.html html.xsl "$draft"
sxml transform --force --output=site/vane.txt text.xsl "$draft"
sxml transform --force --output=site/requirements.json requirements.xsl "$draft"
sxml transform --force --output=site/changes.html --param=old="$earlier" changes.xsl "$draft"
echo "published $draft into site/"

The steps run in order, and set -e stops the script at the first one that fails: every sxml command exits with a status other than 0 when it fails. The validation against vane.xsd comes first, because a stylesheet that meets an element it doesn't expect makes wrong output, not an error. Every transformation writes its own file with --output, and --force replaces the file of the last run.

The check

The schema says what the draft may contain. It cannot say that every reference is cited, or that a key word is marked as one. A query can:

publish-check.xq:

(: Checks a draft before it is published. Problems that make the
   published text wrong are errors and stop publication; open editorial
   matters are warnings. :)
declare namespace spec = "urn:example:spec";
declare option output:method "text";
declare option output:item-separator "&#10;";

declare variable $draft external := "vane.xml";
declare variable $rfc := doc($draft)/rfc;

(: The key words of BCP 14, as a regular expression of whole words. :)
declare variable $keywords :=
  "(^|\W)(MUST|SHALL|REQUIRED|SHOULD|RECOMMENDED|MAY|OPTIONAL)(\W|$)";

let $anchors := $rfc//@anchor
let $errors := (
  for $xref in $rfc//xref[not(@target = $anchors)]
  return `{$xref/ancestor::section[1]/@anchor}: xref to a missing anchor "{$xref/@target}"`,
  for $reference in $rfc//reference[not(@anchor = $rfc//xref/@target)]
  return `references: [{$reference/@anchor}] is never cited`,
  for $text in $rfc/middle//t//text()[not(ancestor::bcp14)]
  where not($text/ancestor::section/@anchor = "terminology")
  where matches($text, $keywords)
  return `{$text/ancestor::section[1]/@anchor}: a key word without bcp14: "{normalize-space($text)}"`
)
let $warnings := (
  for $t in $rfc//t[bcp14][not(@anchor)]
  return `{$t/ancestor::section[1]/@anchor}: a requirement without an anchor`,
  for $cref in $rfc//cref
  return `{$cref/ancestor::section[1]/@anchor}: open note {$cref/@anchor} ({$cref/@source})`
)
return if (exists($errors))
  then error(xs:QName("spec:check"), string-join($errors, "; "))
  else $warnings ! `warning: {.}`

The query makes two lists. An error is a problem that makes the published text wrong: an xref to an anchor that doesn't exist, a reference that no xref cites, a key word written in capitals but without bcp14, which a reader cannot tell from a requirement. (The key words of the Terminology section are quoted on purpose, so the check skips that section.) A warning is open editorial work: a paragraph with a key word but no anchor, which other documents cannot refer to, and a note. When there are errors, fn:error stops the query with all of them in its description, and sxml xquery exits with status 1; otherwise the query writes the warnings, one on each line.

Project: Editing a Specification Without Rewriting It builds a stricter check, which counts the unanchored SHOULD as an error, and the edits that fix what it finds.

The requirements as JSON

Tools that test an SDK, or a tracker of open requirements, want the requirements as data. With the json output method, a stylesheet's result can be a map, written as a JSON object:

requirements.xsl:

<xsl:stylesheet version="4.0" expand-text="yes"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:spec="urn:example:spec"
    exclude-result-prefixes="spec">
  <xsl:import href="common.xsl"/>
  <xsl:use-package name="spec.xsl" package-version="1.0"/>
  <xsl:output method="json" indent="yes"/>

  <!-- The requirements as JSON, for tools: an array of objects. -->
  <xsl:template match="/">
    <xsl:sequence select="{
        'draft': string(rfc/@docName),
        'requirements': array { //t[@anchor] ! spec:requirement(.) }
      }"/>
  </xsl:template>

  <xsl:function name="spec:requirement" as="map(*)">
    <xsl:param name="t" as="element(t)"/>
    <xsl:sequence select="{
        'anchor': string($t/@anchor),
        'number': spec:number($t),
        'keyword': string($t/bcp14),
        'section': spec:number($t/ancestor::section[1]),
        'text': spec:text($t)
      }"/>
  </xsl:function>
</xsl:stylesheet>

The text of each requirement is the text a reader sees, with the xrefs made by the rules of common.xsl: spec:text applies the templates of the stylesheet that imports it.

The changes

The page of changes compares the draft with the earlier one, which the parameter old names. Requirements are matched by anchor: an anchor is given once and never changes, so the same anchor in both drafts is the same requirement, however its text and its number changed. A key finds a requirement by anchor in either document:

changes.xsl:

<xsl:stylesheet version="4.0" expand-text="yes"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:spec="urn:example:spec"
    exclude-result-prefixes="spec">
  <xsl:import href="common.xsl"/>
  <xsl:use-package name="spec.xsl" package-version="1.0"/>
  <xsl:output method="html" indent="yes"/>

  <!-- The earlier draft, compared by requirement anchor. -->
  <xsl:param name="old" select="'vane-00.xml'"/>
  <xsl:variable name="old-draft" select="doc($old)"/>

  <xsl:key name="requirement" match="t[@anchor]" use="@anchor"/>

  <xsl:template match="/">
    <html>
      <head>
        <title>Changes in {rfc/@docName}</title>
      </head>
      <body>
        <h1>Changes from {$old-draft/rfc/@docName} to {rfc/@docName}</h1>
        <table>
          <xsl:apply-templates select="//t[@anchor]" mode="change"/>
          <xsl:apply-templates mode="removed" select="
              $old-draft//t[@anchor][empty(key('requirement', @anchor, current()))]"/>
        </table>
      </body>
    </html>
  </xsl:template>

  <xsl:template match="t" mode="change">
    <xsl:variable name="before" select="key('requirement', @anchor, $old-draft)"/>
    <xsl:variable name="status" select="
        if (empty($before)) then 'added'
        else if (spec:text($before) = spec:text(.)) then 'unchanged'
        else 'changed'"/>
    <xsl:if test="$status != 'unchanged'">
      <tr class="{$status}">
        <td><a href="vane.html#{@anchor}">{spec:number(.)}</a></td>
        <td>{$status}</td>
        <td>
          <xsl:if test="$status = 'changed'">
            <del>{spec:text($before)}</del>
            <br/>
          </xsl:if>
          <ins>{spec:text(.)}</ins>
        </td>
      </tr>
    </xsl:if>
  </xsl:template>

  <!-- A requirement that only the old draft has. -->
  <xsl:template match="t" mode="removed">
    <tr class="removed">
      <td>{@anchor}</td>
      <td>removed</td>
      <td><del>{spec:text(.)}</del></td>
    </tr>
  </xsl:template>
</xsl:stylesheet>

Each requirement of the new draft is added, changed or the same; a requirement whose anchor only the old draft has was removed, and gets a row of its own in the mode removed. The texts are compared as spec:text makes them, so a line broken in another place is not a change. The links point into the HTML page, vane.html, which the script writes next to this one.

When the draft is wrong

Two broken copies show the two guards. In the first, an xref points to RFC6239, which the draft does not have. The schema's key reference from xref/@target to the anchors finds it, and nothing is written:

$ sed 's/target="RFC6238"/target="RFC6239"/' vane.xml > broken.xml
$ sh publish.sh broken.xml; echo $?
broken.xml:98:38: cvc-identity-constraint.4.3: element 'xref': its key sequence is no key sequence of the referenced key (keyref 'xref-target')
1

In the second, the citation of RFC 6238 is gone and a SHOULD has lost its markup. The copy is valid, and the check stops it:

$ sed -e 's| <xref target="RFC6238"/>||' -e 's|<bcp14>SHOULD</bcp14> last|SHOULD last|' vane.xml > unmarked.xml
$ sh publish.sh unmarked.xml; echo $?
publish-check.xq:33:8: spec:check: references: [RFC6238] is never cited; pause: a key word without bcp14: "A pause SHOULD last five minutes."
1

The files in site/ are still those of the last good run. Each step adds one guarantee, and the stylesheets can assume what the steps before them checked: that every target exists, that every key word is marked, that the draft has the structure the schema describes.

Summary

XSLT transforms documents by rules:

  • template rules match nodes with patterns, and xsl:apply-templates moves the processing on; the best rule wins by import precedence and priority;
  • modes process the same nodes in different ways, and a mode with on-no-match="shallow-copy" copies everything you don't change;
  • keys index documents, xsl:number numbers sections and requirements by their position, and xsl:for-each-group groups by value or by position;
  • result documents write many files, and imports, functions and packages organize large stylesheets that share their rules;
  • a script of small checked steps turns one source into every form a document is read in.

XSLT can also transform files too large for memory, as they stream past; Streaming Large Trace Files teaches it on the trace archives of the last project. Next, the diagram tool of Project: Drawing Diagrams with SVG puts XQuery and XSLT together on a different kind of XML: pictures.
