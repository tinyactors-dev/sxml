The sxml Book

A Call Graph from the Code

A call graph has a node for each function of a program and an edge from a function to each function it calls. To build one from the trees that sxml:parse-code makes, we need three things: the functions, the calls inside each function, and for each call, the function it calls. The first two are paths in the tree. The third is the interesting part: the code says registry.getFlag(key), and the graph needs to say registry.getFlag of the module registry.ts, not a method of something named registry.

This section builds the library module graph.xqm (namespace urn:example:graph) one function at a time, and ends with the call graph of both versions of the Vane service as XML.

Functions

In TypeScript's grammar a function declared with function is a function_declaration, and its name is the child whose field is name. With the option positions, each element knows its line:

$ sxml xpath 'sxml:parse-code(unparsed-text("after/flags.ts"), "typescript", { "positions": true() })//function_declaration ! `{@line}: {identifier}`'
"14: summarize"
"18: listFlags"
"27: isOwner"
"31: killFlag"

The exported functions are inside an export_statement, the others are not; // finds both. A program has functions of other kinds too: methods of classes are method_definitions, and a function is often an arrow function assigned to a const, const evaluateAll = (flags) => …, which is an arrow_function inside a variable_declarator. An arrow function passed as an argument, as in flags.map((flag) => flag.evaluate(user)), has no name; its calls are calls of the function around it. graph.xqm says this in two functions:

(: A function with a name of its own: a function declaration, a method,
   or an arrow function or function expression assigned to a const. An
   arrow function passed as an argument has no name, and its calls belong
   to the function around it. :)
declare function graph:is-function($node as element()) as xs:boolean {
  exists($node[self::function_declaration or self::method_definition])
  or exists($node[self::arrow_function or self::function_expression]
                 [parent::variable_declarator])
};

(: The function a node is in. :)
declare function graph:function-of($node as node()) as element()? {
  $node/ancestor::*[graph:is-function(.)][1]
};

(: The name of a function; a method is named after its class. :)
declare function graph:function-name($function as element()) as xs:string {
  typeswitch ($function)
    case element(function_declaration)
      return string($function/*[@field = "name"])
    case element(method_definition)
      return $function/ancestor::class_declaration/type_identifier
             || "." || $function/*[@field = "name"]
    default
      return string($function/parent::variable_declarator/*[@field = "name"])
};

graph:function-of is the nearest function above any node: the ancestor axis goes up from the node, and the predicate [1] on a reverse axis is the nearest one. The functions are named after their module, which is the file name without .ts: flags.listFlags, registry.getFlag, and a method after its module and class, flag.Flag.evaluate.

Calls

A call is a call_expression, and what it calls is its child with the field function. Its text is the callee as the code writes it:

$ sxml xpath 'sxml:parse-code(unparsed-text("after/flags.ts"), "typescript", { "positions": true() })//call_expression ! `{@line}: {*[@field = "function"]}`'
"19: registry.getFlagKeys"
"22: flags.push"
"22: registry.getFlag"
"24: flags.map"
"28: flag.owners.includes"
"32: registry.getFlag"
"33: isOwner"
"36: registry.setPercentage"
"37: audit.record"

Line 22 has two calls, one inside the other: flags.push(await registry.getFlag(key)). The callee is either an identifier (isOwner) or a member_expression, whose object and property fields are the two sides of the dot:

$ sxml xpath --method=xml '(sxml:parse-code(unparsed-text("after/flags.ts"), "typescript", { "highlights": false() })//call_expression)[1]'
<call_expression xmlns:sxml="urn:sxml"><member_expression field="function"><identifier field="object">registry</identifier>.<property_identifier field="property">getFlagKeys</property_identifier></member_expression><arguments field="arguments">()</arguments></call_expression>

The list shows the three kinds of calls a call graph has to tell apart. registry.getFlag and audit.record call functions of other modules of the program, and isOwner a function of the same module. flags.push, flags.map and flag.owners.includes call methods of local values, an array and a string array, which are not part of the program's structure. And other files have calls of functions outside the program: fetch, JSON.parse, createServer, and pool.query, the PostgreSQL pool's method that db.ts calls.

Resolving a callee

What a name stands for in a module comes from the module's imports. In flags.ts:

$ sxml xpath 'sxml:parse-code(unparsed-text("after/flags.ts"), "typescript")//import_statement ! `{.//(namespace_import/identifier | import_specifier/*[@field = "name"])} from {string/string_fragment}`'
"registry from ./registry.ts"
"audit from ./audit.ts"
"Flag from ./db.ts"

A namespace import, import * as registry from "./registry.ts", makes registry stand for the module registry, so the call registry.getFlag is the function registry.getFlag. A named import, import { listFlags } from "./flags.ts" in api.ts, makes listFlags stand for the function flags.listFlags. graph:imports makes a map from each imported name to what it stands for. Imports from packages, node:http, redis and pg, are not modules of the program, so they are left out, and calls to them become external:

(: What the imported names of a module stand for: a namespace import
   names a module, a named import a function of a module. Imports from
   packages (node:http, redis, pg) are left out: calls to them are
   external. :)
declare function graph:imports($program as element(program)) as map(*) {
  map:merge(
    for $import in $program/import_statement
    let $source := string($import/string/string_fragment)
    where starts-with($source, "./")
    let $module := graph:module-name($source)
    return (
      $import//namespace_import/identifier ! { string(.): $module },
      $import//import_specifier/*[@field = "name"]
        ! { string(.): $module || "." || . }
    )
  )
};

The other names a call can start with are the function's own: its parameters and variables. A call through one of them is a method of a local value. graph:locals lists them, and graph:root finds the name a callee starts with, going down the object fields of a chain of member expressions:

(: The names a function declares: its parameters, variables and loop
   variables, and those of the anonymous functions inside it. :)
declare function graph:locals($function as element()) as xs:string* {
  $function//(required_parameter | optional_parameter)/*[@field = "pattern"],
  $function//variable_declarator/identifier[@field = "name"],
  $function//shorthand_property_identifier_pattern,
  $function//for_in_statement/identifier[@field = "left"]
};

(: The name a callee starts with: registry in registry.getFlag, flag in
   flag.owners.includes, this in this.check; empty when it starts with a
   value, as new Date().toISOString does. :)
declare function graph:root($callee as element()) as element()? {
  if ($callee instance of element(member_expression))
  then graph:root($callee/*[@field = "object"])
  else $callee[self::identifier or self::this]
};

graph:callee puts the rules together. It returns a record of the type graph:target, declared at the top of the module with declare record graph:target(id as xs:string, external as xs:boolean), or nothing for a method of a local value:

(: The function a call calls, or nothing for a method of a local value.
   $module is the caller's module, $functions the ids of all functions
   of the program. :)
declare function graph:callee(
  $call as element(call_expression),
  $module as xs:string,
  $functions as xs:string*
) as graph:target? {
  let $callee := $call/*[@field = "function"]
  let $imports := graph:imports($call/ancestor::program)
  let $locals := graph:locals(graph:function-of($call))
  let $root := graph:root($callee)
  return
    if ($callee instance of element(identifier)) then (
      if (map:contains($imports, $callee))
      then graph:target($imports($callee), false())
      else if ($functions = $module || "." || $callee)
      then graph:target($module || "." || $callee, false())
      else if ($locals = $callee) then ()
      else graph:target($callee, true())
    )
    else if ($root instance of element(this))
    then graph:target($module || "." || $callee/ancestor::class_declaration/type_identifier
                      || "." || $callee/*[@field = "property"], false())
    else if ($callee/*[@field = "object"] is $root
             and map:contains($imports, $root))
    then graph:target($imports($root) || "." || $callee/*[@field = "property"],
                      false())
    else if (empty($root) or $locals = $root) then ()
    else graph:target($callee, true())
};

In order:

  1. A plain name that was imported is the function it was imported as; one that names a function of the same module is that function; a local name is a value, not part of the graph; any other name is a function outside the program, such as fetch.
  2. this.check in a method is the method check of the same class.
  3. registry.getFlag, where registry is a namespace import, is the function getFlag of that module. The test that the object is the root (is compares the identity of nodes) keeps out a longer chain such as registry.cache.get.
  4. A callee that starts with a local name or with a value, as in flag.owners.includes or new Date().toISOString, is left out. Anything else, JSON.parse, or client.get and pool.query on a const of the module, is external.

Functions passed as values

listFlags ends with flags.map(summarize). That is a call of flags.map, a method of a local array, but summarize is called too, by map, once per flag. A function of the module named as an argument is an edge of the graph as well; the graph marks it passed.

Calls in loops

A call inside a loop of its function runs once per iteration. The new listFlags calls registry.getFlag in a for … of loop, which the grammar calls a for_in_statement (it has for … in and for … of both). A loop belongs to the call's function only when the nearest function above the loop is the call's function too; a loop in an outer function does not count:

(: Whether a node is in a loop of its own function. :)
declare function graph:in-loop($node as node()) as xs:boolean {
  some $loop in $node/ancestor::*[self::for_statement or self::for_in_statement
                                  or self::while_statement or self::do_statement]
  satisfies graph:function-of($loop) is graph:function-of($node)
};

The graph marks such a call repeated. A loop is not the only way to call something many times: the summarize passed to map runs once per flag as well. The graph says only what the code says in so many words.

The graph as XML

graph:graph takes the parsed modules of a program as a map from the module name to its program element, and returns the graph: a function element for each function, and a call element for each call that resolves to a function, with its line:

(: The call graph of a program, given as its modules by name. :)
declare function graph:graph(
  $modules as map(xs:string, element(program))
) as element(graph) {
  let $functions :=
    for $module in sort(map:keys($modules))
    for $function in $modules($module)//*[graph:is-function(.)]
    return { "module": $module, "element": $function,
             "id": $module || "." || graph:function-name($function) }
  return <graph>{
    for $function in $functions
    return <function id="{ $function?id }" line="{ $function?element/@line }"/>,
    for $function in $functions
    for $call in $function?element//call_expression
    where graph:function-of($call) is $function?element
    let $target := graph:callee($call, $function?module, $functions?id)
    (: A function of the module passed as an argument is called from
       here too, by the function it is passed to. :)
    let $passed := $call/arguments/identifier
                   [$functions?id = $function?module || "." || .]
                   ! graph:target($function?module || "." || ., false())
    for $to at $position in ($target, $passed)
    return <call from="{ $function?id }" to="{ $to?id }" line="{ $call/@line }">{
      if (graph:in-loop($call)) { attribute repeated { "true" } },
      if ($to?external) { attribute external { "true" } },
      if ($position > count($target)) { attribute passed { "true" } }
    }</call>
  }</graph>
};

The for $to at $position in ($target, $passed) clause makes one call element for the callee and one for each function passed to it; the position tells them apart. The conditional attributes use the braced form of if, if (C) { E }, which needs no else.

graph:read reads a directory of TypeScript files into that map, with the EXPath File functions:

(: The modules of a directory, parsed. :)
declare function graph:read(
  $directory as xs:string
) as map(xs:string, element(program)) {
  map:merge(
    for $file in file:list($directory, false(), "*.ts")
    return { graph:module-name($file):
               sxml:parse-code(file:read-text($directory || "/" || $file),
                               "typescript", { "positions": true() })/program }
  )
};

graph.xq prints the graph of a directory:

(: The call graph of the TypeScript files in a directory, as XML: one
   version of the Vane service, before or after. :)
import module namespace graph = "urn:example:graph" at "graph.xqm";

declare option output:indent "yes";

declare variable $directory as xs:string external := "before";

graph:graph(graph:read($directory))

Asking the graph

Once the graph is a document, questions about the program are short XPath expressions. Save it first:

$ sxml xquery --allow-file-access --param=directory=after graph.xq --output=after.xml

Who calls registry.getFlag, and where?

$ sxml xpath --context-item=after.xml '//call[@to = "registry.getFlag"] ! `{@from}, line {@line}{if (@repeated) then ", in a loop" else ""}`'
"flags.listFlags, line 22, in a loop"
"flags.killFlag, line 32"

Which functions does no call reach? Those are where the program is entered:

$ sxml xpath --context-item=after.xml '//function[not(@id = //call/@to)]/@id/string()'
"api.start"

Which functions outside the program does it use?

$ sxml xpath --context-item=after.xml 'distinct-values(//call[@external]/@to)'
"JSON.parse"
"createServer"
"JSON.stringify"
"fetch"
"pool.query"

What a call graph from the code cannot see

kinds/flag.ts has the other kinds of functions: two methods, an arrow function assigned to a const, and an arrow function passed to map:

// Three kinds of functions: methods, an arrow function assigned to a
// const, and an arrow function passed as an argument.
class Flag {
  evaluate(user: string): boolean {
    return this.check(user) && log("evaluate");
  }

  check(user: string): boolean {
    return /^beta-/.test(user);
  }
}

const evaluateAll = (flags: Flag[], user: string): boolean[] =>
  flags.map((flag) => flag.evaluate(user));

function log(text: string): boolean {
  console.log(text);
  return true;
}

$ sxml xquery --allow-file-access --param=directory=kinds graph.xq
<graph>
  <function id="flag.Flag.evaluate" line="4"/>
  <function id="flag.Flag.check" line="8"/>
  <function id="flag.evaluateAll" line="13"/>
  <function id="flag.log" line="16"/>
  <call from="flag.Flag.evaluate" to="flag.Flag.check" line="5"/>
  <call from="flag.Flag.evaluate" to="flag.log" line="5"/>
  <call from="flag.log" to="console.log" line="17" external="true"/>
</graph>

The methods, this.check and the call of log are found. But evaluateAll calls Flag.evaluate for each flag, and the graph does not say so: flag.evaluate(user) is a call on flag, a parameter of the arrow function, and the graph cannot know what flag is without the types. The code has them (flags: Flag[]), and a longer query could follow the type annotations to the class. Other calls no query of the code can resolve: a function chosen at run time, from a map of handlers or by a name in a string. A call graph from the code is a good approximation, and for this project it is exact: the Vane service calls its modules through namespace and named imports, and everything else is a local value or outside the program.
