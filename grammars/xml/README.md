# XML 1.0 grammar

A strict tree-sitter grammar for XML 1.0 (Fifth Edition) documents, used by
sxml's XML parser (docs/DECISIONS.md, D12). The concrete syntax tree it
produces is walked by the tree builder, which builds the XML tree arena and
then frees the concrete syntax tree.

| File | Origin |
| --- | --- |
| `grammar.js` | Hand-written. Production numbers refer to XML 1.0 (Fifth Edition). |
| `src/scanner.c` | Hand-written external scanner (tag stack, text tokens, PI targets). |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | Generated by `tools/generate-grammars.sh xml`; committed. |
| `test/corpus/*.txt` | tree-sitter corpus tests. |
| `tree-sitter.json` | Grammar metadata for the CLI. |

Regenerate and test (needs `npm ci --prefix tools`):

```sh
tools/generate-grammars.sh xml
cd grammars/xml && ../../tools/node_modules/.bin/tree-sitter test
```

Parse one file with the CLI: `tools/node_modules/.bin/tree-sitter parse -p grammars/xml file.xml`.

In the corpus files the input starts on the line right after the header's
closing `===` line. Leading whitespace is significant (it is not allowed
before the XML declaration), so there is no blank line there.

## Contract with the tree builder

The input is UTF-8 (or UTF-16, which tree-sitter decodes itself). The
builder detects and transcodes other encodings first (4.3.3, Appendix F).
A leading byte order mark is accepted and hidden.

**Any `ERROR` or `MISSING` node means the document is not well-formed.**
A tree without them is well-formed only after the checks listed under
"What the tree builder checks" pass.

## What the grammar checks

- Every production of the document grammar, [1]–[83] except the external
  subset ([30]–[31], [61]–[65]) and text declarations ([77]–[78]), which a
  non-validating processor that reads no external entities never parses.
- [2] Char in every text token: character data, attribute values, entity
  values, comments, PIs, CDATA sections, system literals. Undecodable bytes
  are rejected too.
- [4], [4a] name characters exactly as in the Fifth Edition, outside ASCII
  included; [7] name tokens; [13] public identifier characters.
- WFC: Element Type Match (3): the external scanner keeps a stack of open
  start tags and accepts an end-tag name only if it equals the innermost one.
- WFC: PEs in Internal Subset (2.8): parameter-entity references are
  accepted between declarations only; inside a declaration (including an
  entity value) they are an error.
- The XML declaration only at the very start (after an optional byte order
  mark), with its parts in order; no PI target `xml` in any case ([17]).
- No `]]>` in character data ([14]); no `--` inside comments, and no comment
  ending in `--->` ([15]).
- A default declaration in every attribute definition ([53]); `)*` after
  mixed content that names elements ([51]); choice and sequence groups not
  mixed ([49], [50]).
- Exactly one root element, nothing but Misc after it, at most one document
  type declaration, before the root.

## What the tree builder checks

Well-formedness constraints and rules that a context-free grammar does not
express (section numbers of XML 1.0 Fifth Edition, and of Namespaces in XML
1.0 Third Edition where marked NS):

1. **Encoding** (4.3.3): detect from the byte order mark or the declaration,
   transcode, and reject a declared encoding that contradicts the bytes.
2. **End-of-line handling** (2.11): `CR LF` and lone `CR` become `LF` in all
   text, before any other processing.
3. **WFC: Unique Att Spec** (3.1): no attribute name twice in one tag.
4. **WFC: Legal Character** (4.1): a `character_reference` must denote a
   [2] Char. Parse the digits with overflow checks (values far beyond
   `#x10FFFF` occur in the tests).
5. **WFC: Entity Declared** (4.1): every `entity_reference` names a declared
   entity or one of `lt gt amp apos quot` (4.6), when the document has no
   DTD, or only an internal subset without parameter-entity references, or
   `standalone="yes"`. Otherwise an undeclared reference is a validity error
   only, and the reference stays unexpanded. A reference in an attribute
   default must follow the entity's declaration.
6. **Declarations after unread parameter entities** (5.1): after a
   `parameter_entity_reference` to an entity that is not read, and when
   `standalone` is not `yes`, entity and attribute-list declarations are not
   processed.
7. **WFC: Parsed Entity** (4.1): no reference to an unparsed entity (one with
   `NDATA`).
8. **WFC: No Recursion** (4.1): an entity must not refer to itself, directly
   or indirectly.
9. **Well-formed parsed entities** (4.3.2): the replacement text of an
   internal general entity referenced in content must match [43] content.
   Build the replacement text (4.5: character references and parameter
   entities expanded, general entity references kept), then parse it with
   this grammar wrapped in a dummy element (`<x>` text `</x>`): a mismatched
   or unclosed tag, `]]>` or a bad character inside it is then an `ERROR`.
10. **WFC: No External Entity References** (3.1): no reference to an
    external entity in an attribute value, directly or through other
    entities, also in attribute defaults (Fifth Edition erratum E12).
11. **WFC: No < in Attribute Values** (3.1): the replacement text of an
    entity referenced in an attribute value, directly or indirectly, must not
    contain `<`; this also applies to attribute defaults in the DTD (3.3.2).
12. **Attribute-value normalization** (3.3.3), and default attributes from
    `attribute_list_declaration` (3.3.2): for one element and attribute the
    first definition wins; attribute types other than CDATA get the extra
    whitespace collapsing.
13. **Entity declarations**: the first declaration of an entity wins (4.2).
14. **Namespaces** (NS 3, 4, 5): QName syntax (at most one colon, not first
    or last); every prefix bound; `xml` and `xmlns` prefixes and namespaces
    used only as allowed; no `xmlns:p=""` in XML 1.0; attribute uniqueness by
    expanded name; no colon in PI targets, entity names or notation names.
15. **XML 1.1**: the grammar accepts `version="1.1"` and parses the document
    by the 1.0 rules (1.0 Fifth Edition, 2.8 permits this). Whether sxml
    rejects or accepts such documents is the builder's decision.
16. A document node always has a `root` element. The grammar guarantees it
    for parsed documents; it is listed here so a builder that parses
    fragments by wrapping keeps the check.

## External scanner

The scanner produces the element names, `/>`, `character_data`,
`cdata_text`, `comment_text`, processing-instruction targets and contents.
Each text token checks [2] Char and its closing delimiter.

tree-sitter restores the scanner state from at most 1024 serialized bytes
before every external token, which cannot hold a stack of names for a deep
document. The stack is therefore persistent: every distinct pair
(parent frame, element name) is stored once in an append-only table inside
the scanner, and the serialized state is the 4-byte index of the innermost
frame. Equal stacks have equal indices, so tree-sitter's state comparisons
stay exact. The table lives as long as the `TSParser` keeps the language;
its size is bounded by the number of distinct element paths parsed. The
scanner allocates with `ts_malloc`/`ts_calloc`/`ts_realloc`, the runtime's
allocator (D12 exemption for the parse step). In error recovery it offers no
token, so recovery cannot make bad input look well-formed.

`cdata_text` may come in pieces: a token cannot end two characters before
the current position, so for `]]]>` the scanner returns the extra `]`
separately.

## Validation

Measured 2026-10-16 with the tree-sitter CLI 0.27.1 (`tree-sitter parse -q`).

**QT4 and XSLT 4.0 test suites** (pinned commits of D13): all 3612 `*.xml`
files under `third_party/qt4tests` and `third_party/xslt40-test`. 3583 parse
cleanly. The 29 with `ERROR` nodes:

- 11 are not UTF-8 (9 ISO-8859-1, 2 UTF-16); after transcoding with
  `iconv`, 8 parse cleanly and 3 are not well-formed anyway (no root
  element, or a missing end tag).
- 18 are not well-formed, mostly on purpose: names with U+00BC
  (`fn/id/BCisInvalid.xml`, `InvalidUmlaut.xml`), control characters
  (`fn/id/badxml.xml`), several root elements or text only (external-entity
  fragments such as `strm/si-for-each-group/chunk00*.xml`,
  `fn/base-uri/dir/data.xml`, `insn/copy/ent22.xml`), no root element
  (`fn/stream-available/dtd-only.xml`, `fn/resolve-uri/level1/pi.xml`),
  truncated or unclosed documents (`fn/stream-available/unfinished.xml`,
  `strm/si-for-each-group/account*.xml`, `si-group-039-Formatted.xml`), and
  an empty file.

No well-formed UTF-8 file in either suite produces an error. (The CLI
decodes UTF-16 with a byte order mark itself; a caller of the library must
pass `TSInputEncodingUTF16LE`/`BE` for such input.)

The same inputs, and the W3C suite below, were also parsed through the
library (`ts_parser_parse_string`, generated parser and scanner built with
AddressSanitizer and UndefinedBehaviorSanitizer): same verdicts, no
sanitizer findings.

**W3C XML conformance suite** (`xmlts20130923.tar.gz`): tests with
`ENTITIES="none"`, XML 1.0 and Namespaces 1.0 recommendations, Fifth Edition
where an edition is given; non-UTF-8 inputs transcoded by their byte order
mark or declared encoding (left as they are when the encoding name is
unknown or invalid).

| Type | Tests | Parse cleanly | `ERROR` |
| --- | ---: | ---: | ---: |
| valid | 601 | 601 | 0 |
| invalid (well-formed) | 175 | 175 | 0 |
| not-wf | 948 | 78 | 870 |
| error | 9 | 9 | 0 |

All 78 not-wf tests that parse cleanly break a constraint from the builder
list above: entity declared, parsed entity, no recursion and well-formed
replacement text (28), legal character in character references (15,
including overflow tests), unique attribute specification (4), no `<` and no
external entities in attribute values (8), namespace constraints (21), and
encoding mismatches (2).

Throughput with the CLI is about 2.5–10 MB/s, the same as
tree-sitter-grammars/tree-sitter-xml on the same input. A 5000-level nesting
of long names parses correctly.

## Why not tree-sitter-xml

tree-sitter-grammars/tree-sitter-xml (MIT) was studied (NOTICE) and not
used: it accepts ASCII names only in the grammar but classifies tag names
with the locale-dependent `iswalnum` and truncates non-ASCII codepoints to
`char` on its tag stack; its serialized tag stack is cut at 1024 bytes, after
which correct end tags fail to match; its serializer frees the tag names it
writes; it calls `abort`; it allows whitespace before the XML declaration,
attribute definitions without a default declaration and parameter-entity
references inside internal-subset declarations; its PI content cannot span
lines; and it checks no [2] Char constraint.

The conformance numbers come from `test/xml-conformance.py` (usage in its
docstring); the suite itself is not fetched by `tools/fetch-test-suites.sh`.
