# Query grammars: XPath 4.0, XQuery 4.0, XSLT 4.0 patterns

Three tree-sitter grammars share one design (docs/DECISIONS.md, D12 and D29):

| Directory | Start rule | Source |
| --- | --- | --- |
| `grammars/xpath` | `xpath` | XPath 4.0 Appendix A (QT4 CG draft) |
| `grammars/xquery` | `module` | XQuery 4.0 Appendix A, inherits `xpath` |
| `grammars/xslt_pattern` | `pattern` | XSLT 4.0 section 6.3 and Appendix E, inherits `xpath` |

- `grammars/xpath/lexical.js` holds the keyword lists and name expressions.
- `grammars/common/query_scanner.h` is the external scanner of all three
  (comments, string templates and constructors, direct constructors,
  pragmas). Each `src/scanner.c` instantiates it.
- `src/` is generated by `tools/generate-grammars.sh` and committed.
- `test/corpus/` holds the tree-sitter corpus tests; run
  `tools/node_modules/.bin/tree-sitter test` inside a grammar directory.

## Conformance of the parse

`tools/qt4-parse-check.py` parses every applicable query of the QT4 test
suite (and, with `--spec XT40`, every pattern in the XSLT 4.0 test suite)
and compares the parse with the expected result. A false reject is a valid
query that does not parse; a false accept is a query whose only expected
result is XPST0003 but that parses. Measured on 2026-10-16 against the
vendored suites (qt4tests `16645335`, xslt40-test `91328fbf`):

| Spec | Valid queries | False rejects | XPST0003 queries | False accepts |
| --- | ---: | ---: | ---: | ---: |
| XP40 (`xpath`) | 32,118 | 0 (0.00%) | 363 | 2 |
| XQ40 (`xquery`) | 43,663 | 0 (0.00%) | 772 | 3 |
| XT40 patterns (`xslt_pattern`) | 19,168 | 3 (0.02%) | n/a | n/a |

Not counted above:
- XQuery Update, Full Text and XSLT-dependent test cases ("extension
  syntax"). The XQuery Update Facility 3.0 (D187) is in grammars/xquery:
  every query and library module of the upd-* test sets parses (1,159
  texts). So is XQuery and XPath Full Text 3.0 (D214): of the 685 ft-*
  test cases, the 667 that expect a parse parse, and the 18 rejected are
  exactly those that expect XPST0003 (LetScoreExpr-2 allows it). Its 43
  keywords are not reserved words (the lexer returns one only where the
  parse state expects it), which keeps the name positions and most of
  the tables as they were: the compiled parser grows by about 500 KB.
- Test cases that need XML 1.1 or an XML 1.0 edition before the fifth (all
  parse).
- 23 (XP40) and 47 (XQ40) test cases whose result allows XPST0003 among
  other outcomes.
- XQ40: 149 library modules named by test cases; 145 parse, the 4 others
  are deliberately invalid or use XQuery Update.
- XT40: 136 patterns use syntax the XSLT 4.0 draft has dropped (`~T` and
  `type(T)` type patterns, record patterns with field declarations); 64
  patterns come from stylesheets that a test expects to fail with XTSE0340.

The remaining false accepts are left to the tree-building step:
- `Lookup-156`, `MapConstructor-025a`: a prefixed name as lookup key. The
  grammar accepts it so that `a:b` stays one token (A.3 longest token).
- `itemTypeDecl-077`: string field names in a `%constructor` record
  declaration, a static rule rather than a grammar rule.

The three pattern false rejects are invalid patterns in DocBook stylesheets
(`comment[]`, a pattern made of `|` only) that no test compiles.
